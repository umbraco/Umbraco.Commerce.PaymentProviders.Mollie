# Upgrade to Umbraco 19

From Umbraco Commerce `[18.0.0, 18.999.999)` (CMS 18) to Umbraco Commerce `19.0.0-beta.1` (CMS `19.0.0-beta1`, tag `release-19.0.0-beta1`).
Branch `v19/topic/cms-19-upgrade` → PR into `release/19.0.0`, both cut from `main` (`7519d70`).

**Targets CMS release:** `release-19.0.0-beta1`, via Umbraco Commerce `19.0.0-beta.1` (MyGet `umbracoprereleases`). The package's own version is `19.0.0-beta.1`.

The package depends on `Umbraco.Commerce.Core`, `Mollie.Api` and `Microsoft.AspNetCore.WebUtilities`, never on `Umbraco.Cms.*` directly, so the CMS breaking changes reach it only through Commerce. Commerce's own v19 inventory (Core repo, `docs/upgrades/v19.md`) is the source for those; the Stripe provider's v19 upgrade is the reference run.

## Decisions

- Mollie.Api major taken in this upgrade (maintainer brief, 02-11-2026: take majors during a major upgrade when tests can cover them).
- Mollie.Api 5 errors: every call ends in `EnsureSuccess()`, so a Mollie API error still throws `MollieApiException` as in v4 and Commerce's existing error handling is unchanged.
- Amount rounding: `MollieAmounts.Create` rounds to the currency's decimals (2, or 0 for JPY/ISK) with `MidpointRounding.AwayFromZero`, the same as v4's `ToString("0.00")`. Without it, a value such as a derived tax amount with 3+ decimals would be rejected by Mollie.
- VAT rates are sent with 2 decimals (`"21.00"`, `"0.00"`) as before.
- The existing `#pragma warning disable CS0618` around Mollie's own `OrderClient` stays: it reads legacy orders created with the Orders API before v17. It hides a Mollie.Api deprecation, not an Umbraco removal.

## Breaking changes for consumers

- Requires Umbraco Commerce 19 (.NET 11).
- Mollie.Api 5.1 (was 4.x): sites that reference Mollie.Api themselves move with it (result-based `MollieResult<T>`, `Amount.Value` is a `decimal`, `DateTimeOffset` dates, `Polly.Core` instead of `Microsoft.Extensions.Http.Polly`). See Mollie's v4 → v5 migration guide.
- Removed the `mollieOnetime*` localization keys of the old Mollie (One Time) v1 provider (marked "Will be removed in v17"; the provider itself was already gone). The v2 provider's `mollieOnetimeV2*` keys are unchanged.

## Follow-ups

- Live smoke in Mollie test mode before 19.0.0 final (needs a Mollie test API key):
  1. Payment with order lines, a discount, shipping and a payment fee: Mollie accepts the lines (amounts and VAT rates).
  2. Single and multiple payment methods in the setting (`method` vs `methods`).
  3. Webhook and redirect callbacks finalize the order; cancelled and failed payments go to the cancel and error pages.
  4. Manual capture, then refund (partial and full), then cancel an authorization.
  5. A legacy order with only `mollieOrderId` (Orders API) still resolves its payment id.
  6. A currency with 0 decimals (ISK or JPY), if the account supports one.
- Mollie's `MOLLIE001` analyzer is clean; keep it that way when adding calls.
- The `mollieOnetimeV2MetaDataMollieOrderIdLabel` text still says "Switch to Payment Id in v17". Decide whether the legacy order id lookup can go.
